# P4.40｜见势「项目决策档案」第一版交付与证据合同

日期：2026-10-10。接续 P4.38/P4.39 的「先看到有据项目，再选择研究路径」；本阶段**只改造 3 家已有 L3/L4 经营证据的公开案例** Carrd、Plausible、NerdWallet，不创建其他未经审核的项目档案。

## 目标

用户进入具体公司时，能在页面顶部直接了解**要不要研究、研究什么、最需要验证什么**，而不是只能阅读背景材料。关键区别：

- **原企业有经营证据**：属于经营事实/自述的历史记录，需要原出处、归属、报告期间和审计性质。Carrd 和 Plausible 的历史收入为自述，NerdWallet 的 2025 年 10-K 为公司级监管历史财务。
- **个人能不能复制**：另一个问题。现有三家都没有经过新进入者真实需求、付费获客、执行成本与可复制成功的完整验证。**已验证可直接启动的项目：0**。
- **一人小资金的建议**：属于编辑性低成本验证研究，不是公司的营收或任何付费成功承诺。

## 首次交付的交互与数据

沿用原有 `scripts/release/p423_build_project_proofs.py`，新增纯离线模型 `scripts/release/p440_decision_report.py`。复用已冻结并通过 P4.28 校验的 `config/p428_solo_startup_profile.json` 及 P4.24 原始经营证据，没有新的手工二次录入公司收益。

每张详情页在「30 秒看懂这门生意」之前增加统一「研究决策卡」：
1. **判断等级（非成功概率）**：Carrd `TEST_IDEA_ONLY`（可以先研究一个低成本需求测试方向）；Plausible `SKILL_GATED`（开发运维能力门槛高，不作为新手首选）；NerdWallet `NOT_SOLO_STARTUP`（成熟公司标杆，不建议个人小资金照搬）。
2. **启发的最小需求实验**：直接来自 P4.28 的 `prototype`；明确是受公司启发的待测方向，不能等同原企业业务营收模式。
3. **技能/资源与未知成本**：逐项采用 `skills`、`capital_logic`、`solo_logic`；没有已核实的预算数字就标未核实，不补任何人民币额度/利润率。
4. **原公司历史经营证据**：调用原 `derive_digest`，保留 L3/L4、自报 vs 监管公司合并报表、历史期间、原始 `https://` 证据链接、归属性和非当期/非可复制限制。
5. **三项可执行的研究待办**：P4.28 `first_step`（要做的需求实验）、`blocker`（继续投入之前缺的证据）、P4.24 `next_research`（继续核查原公司资料）。这些仍是**待执行**的研究计划，不表示已经访谈、获得试单或确认需求。

同时将项目目录的三张卡片增加“一人起步判断 / 待补验证”，原项目简介、搜索、证据等级排序和外部证据链接保留，未新增不合格项目。

## 审核不变量

- 只允许已正式准入且具 P4.24 历史经营证据的三家，拒绝单纯产品官网 L1 / 平台归属 L2。
- 账期或原始 HTTPS 来源缺失、公司 ID 不在 P4.28 适配档案、技能/资本/验证步骤缺字段，生成直接 **FAIL CLOSED**。
- `ready_for_launch` 必须为严格 `false`；即便上游误标 true，也拒绝“可直接创业”的暗示。
- `financial_evidence_verified`、`income_projection` 等计算无新增；原L3历史自述与L4合并监管财报等级不变，不宣传2026最新企业收入。
- 保留原公开三个详情 URL、已审核目录、首页推荐、源图像、灯箱、黑白主题；`web/dist` 原有安全发布检查及无内部数据要求不降低。
- 产品研发与采集完全隔离：不改 HN / RSS / GitHub 最多10个来源请求/日，不触及 Supabase Production、Cloudflare配置/账单或受限挂牌站。
- 这版是**规则与内容驱动的静态决策报告**，不是完整 AI 研究助手，更不是个人可启动创业项目认证。
