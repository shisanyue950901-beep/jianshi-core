# P4.25｜见势只收录有项目级经营证据的商业案例

生效：2026-10-09。该政策覆盖正式网站 `/projects/` 目录、具名详情页、首页具名项目清单、sitemap 与静态构建后的公开 JS 内容。**不等于强制删除私有仓库里仍待核实的研究资料。**

## 严格正式收录规则
- **L4 监管财务证明**：企业法律主体能够明确归属，公开可追溯的监管申报或经过审计的历史公司财务记录，必须标明报告期、企业集团范围，不能推断未来利润。
- **L3 具名经营披露**：可归属于某个项目的创始人原始访谈或企业署名历史营收／MRR／ARR／实际付费用户披露；允许进入*有经营证据*栏目，但必须永久醒目注明“自述未经独立审计”。
- **L2 平台上架/创作者身份旁证不足收录**。例如 Notion 上架、Amazon 作者专题不能证明本项目实际成交、当前版税或净利润。
- **L1 只有项目官网、定价页或商业模式说明不足收录**；行业类别的匿名交易市场数据也不能借给某家具体公司。
- 任一字段不符合合法 HTTPS 来源、归属合法或资质要求 → **FAIL_CLOSED**，不得用于晋级。

## 本次审核状态
正式收录：**NerdWallet（L4）、Carrd（L3）、Plausible（L3）**。首批 3 个；它们的公开资料均是**历史财务或历史收入披露**，不是 2026 年当前项目利润排名。

未通过正式收录：**17 个**项目仍在私有研究队列，供以后补证与复核使用。即使 L2 得到平台归属证据，也不会出现在正式具名商业清单。网站不得通过 JavaScript 携带未批准项目的标题、简介或来源直接暴露。

## 构建和验证
- `scripts/release/p425_public_admission.py` 对 P4.24 的具名原始证据台账执行资格判定；只允许具有已审核出处、具体经营披露类别与资料身份的项目进入正式榜。
- `p423_build_project_proofs.py` 可以读取 20 份内部候选档案，但构建时仅输出 **3 个获准独立档案＋1 个索引**；重建之前清理原有项目输出目录，防止旧 L1/L2 网页遗留。
- `p412_build_public.py` 在写入生产首页之前剔除未批准的具名项目记录。原有 8 个 3D WebP 封面继续保留，原先 Easlo、Louise 两张仅作为**明确标注非案例的概念插画**，没有企业名称、官方来源或误导性经营结论。
- sitemap 仅保留首页、隐私、行业证据页、正式项目索引＋3 个具名档案，共 **7 项**。原来 17 个具名项目页面不再打包；云端历史版本/搜索引擎缓存另需独立检视。
- 发布配置仍严格使用 `web/dist`，所有公司证据、CI/敏感源防泄漏扫描与 SHA 对应门槛通过才能上线。
- 收录数量不是 KPI；宁缺毋滥。连续多日没有新的合格商业案例时，宁可保持 3 个，也不得制造“今日热度”。

## 持续补证责任
系统负责持续搜集**合法公开**的监管申报、署名经营披露、可信平台交易/客户旁证，记录来源/时间/类型与下一步核查问题；用户无需人工核验 17 家。后续自动发现与来源交叉审核仍按 P4.25 路线推进，**不能把每 6 小时自动排序说成自动全量事实审核**。
