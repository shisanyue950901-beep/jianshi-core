# P4.28｜见势默认推荐：一个人、小资金、从零启动

用户决策：默认面向一位创业者，资金较少，从零启动，不预设团队、现成客户或编程能力。

## 新增受控推荐规则
- 只有已经达到严格 L3/L4 公司历史经营证据门槛的案例才能进入正式案例。过去的创始人、公司、监管披露不等于创业成功率。
- 创业适配从案例经营真实性拆开：能否一人先验证需求、是否囤货、是否需要雇佣团队、技术/合规门槛、获客成本、服务交付成本、是否有实际新客户愿意付费。未知都标记未知，不通过缺失指标打高分。
- 尚未提供具体人民币预算，不虚构“零成本”“低于 X 元”等数字。小资金意味着先验证、控制投入，不等于工具与人力没有成本。
- 若拟被直接启动的案例缺少实际独立客户需求和投入/获客可行性验证，`ready_for_launch=true` 会让构建失败关闭。

## 当前官方案例评估
1. Carrd · L3：创始人有历史 MRR/ARR 自述。针对单人低资金的验证型假设是“先用现成工具给细分商家做单页网站服务、争取第一笔试单”，不等于 Carrd 的建站 SaaS 模式已被证实可复制；仅标为 `TEST_IDEA_ONLY`。
2. Plausible · L3：公司有历史 ARR/付费用户自述，但研发、维护、部署、获客门槛不能当作零技术低成本项目。`SKILL_GATED`，仅作为有技能后研究的方案。
3. NerdWallet · L4：有合并历史财报，但内容、规模、流量、法律合规和团队经营门槛不适合默认单人从零复制。`NOT_SOLO_STARTUP`，成熟标杆。

### 对用户展现
网站首屏默认显示“一人 · 小资金 · 从零启动”，推荐一项‘可先做小范围需求测试’的路径，其他两项明确降级。每项分开展示可归属的历史经营证据、从零测试方案、预计需要具备的能力和**尚缺的市场需求/获客/交付/具体费用证据**。当前 **0 个通过直接创业启动门槛**。

## 工程约束
- 新配置 `config/p428_solo_startup_profile.json` 冻结人群与案例适配；P4.27 的生成器使用显式准入状态排序，不根据历史收入金额直接打‘推荐创业’分。
- 不允许无经营依据的17个候选进入正式案例榜，6类行业匿名挂牌仍不得归到公司；完整8张WebP与3D动效、浅/深切换保留。
- 未新增定时付费调用，不更改Supabase生产数据/Edge/Cron、Cloudflare套餐、历史PR#52；TinyFish仍不调用。
- 每次发布需CI/安全门禁成功；CDN真实浏览器与Safari手机视觉验收独立标记待确认。

## 下一阶段：真正的可启动推荐
系统优先搜索可明确归属的单人经营数据与客户付费资料；另外独立验证目标客户、服务测试订单/订金、工具/域名/履约成本与可重复获客。通过小资金、单人交付和有效付费证据的候选才能升级为正式可启动创业推荐。仍须区分创始人的历史成绩与新创业者的可复制性。
