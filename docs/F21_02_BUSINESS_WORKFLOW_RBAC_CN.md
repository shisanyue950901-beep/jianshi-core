# F2.1-02｜业务状态机、操作权限与异常合同

状态：WORKFLOW_CONTRACT_ONLY。V2 功能尚未对生产用户开放；本文件只限定 staging 实现。

## 1. 角色及最小权限

| 角色 | 公共内容 | 自己的私有内容 | 别人的私有内容 | 审核发布 |
|---|---|---|---|---|
| 游客 | 只读已审核 | 无 | 禁止 | 禁止 |
| 个人账户 | 只读 | 收藏与本人学习记录 | 禁止 | 禁止 |
| 创作者 | 只读 | 本人档案/作品/申请 | 禁止 | 提交待审核，不可批准 |
| 企业负责人 | 只读 | 自企业成员和需求草稿 | 其他企业禁止 | 提交认证/需求，不可自行批准 |
| 企业成员 | 只读 | 明确授予的自企业空间 | 其他企业禁止 | 按授予权限操作，不可审批 |
| 内容审核员 | 只读 | 分配的内容审核队列 | 企业保密字段默认无权 | 内容审核，不能批准自己的稿件 |
| 业务审核员 | 只读 | 已授权审核范围 | 无关企业保密字段不可读 | 企业、需求与作品的专属审核 |
| 系统管理员 | 只读 | 最小化且有日志的管理访问 | 仅按职责审计 | 受控状态改变与封禁 |

管理员权威应来自不可被用户编辑的服务端授权数据，不依赖 user_metadata。服务端每次检查组织所有权、成员角色与 JWT 会话有效性；不只检查是否 logged in。

## 2. 需求状态机（枚举与前置条件）

草稿 DRAFT → 提交审核 PENDING → APPROVED/REJECTED；APPROVED + 授权公开摘要 + 企业 VERIFIED → PUBLISHED；公开需求可接收申请；企业撤回后 CLOSED，不接受新申请。
任何时刻审核员可 SUSPENDED，恢复必须重新核验；每次状态变更写审计事件。
拒绝后编辑回 DRAFT，再提交；不允许 DRAFT→PUBLISHED、REJECTED→PUBLISHED，也不允许企业自己直接给需求 APPROVED。
订单类型 PROJECT / 岗位类型 JOB 必须分表或使用经验证的区分字段；岗位须补充地区/雇佣形式/职责，项目需成果/时限/验收/授权。

## 3. 创作者和作品

档案 DRAFT→PENDING→APPROVED/REJECTED/SUSPENDED；本人公开同意可随时撤回，撤回立即隐藏公开摘要；APPROVED 但不同意公开也不可出现在人才目录。
作品须标识 PRACTICE、PERSONAL 或 CLIENT_AUTHORIZED。只有 rights_confirmed + review APPROVED + 档案公开同意才可上架；个人联系方式默认不公开。
申请 PENDING→SHORTLISTED/DECLINED/WITHDRAWN/ACCEPTED；仅允许已审核且公开需求，禁止跨账号冒名投递；同一用户同需求最多一条申请，过期或关闭不可申请。

## 4. 异常、审计与伪造测试

每次操作验证主体、对象、状态、版本号和幂等键。重复请求、并发申请、未授权组织、已撤回同意和系统停机都 FAIL_CLOSED；仅在受控角色下重试。
审核事件记录实体类型/ID、操作者、操作前后状态、时间、原因、追踪 ID；公开站绝不显示私有原因或联系方式。
测试用企业 A/B、创作者 A/B、两名审核员及一名管理员均为合成账号：不少于 40 条正向/负向角色×资源×操作检查，每条失败需留脱敏诊断。
