# 见势 JIANSHI 2.0｜商业战略与 Super-i 页面模板的统一施工基线

**冻结日期：2026-10-13｜性质：UI / 信息架构执行标准｜不更改已确认商业模式**

## 0. 上下游优先级（出现冲突时按此顺序）

1. **最高优先级：B0 双业务战略** `JIANSHI2_B0_DUAL_TRACK_POSITIONING_CN.md`：唯一主业务为「个人创业机会发现与决策」，不局限于 AI；中小企业 AI 落地服务为第二业务线，先人工验证。
2. **用户体验硬规则** `JIANSHI2_PUBLIC_PLAIN_LANGUAGE_RULES_20261013_CN.md`：用户一眼看不懂的解释与术语不占用公开页面；复杂来源核查保留后台或放在详情后段。
3. **已批准视觉方向** `JIANSHI2_F1_PRODUCT_UI_FREEZE_20261011.md`：视觉借鉴 Super-i 的信息层级、内容大卡片、渐变、交互节奏；见势必须是独立原创视觉、页面、品牌资产和代码。
4. **参考资料** 2026-10-11 形成并保存在项目资料库的 `Super-i_全站功能与UI界面盘点_2026-10-11.md`，以及该文件记录的公开参考 URL。它是一份**公开信息与文字线框盘点**，并非 Super-i 可复用源代码、完整 CSS 组件库或像素级设计稿。不能擅自把它说成见势已整合的成品前端模板。
5. **已经存在的见势原创 UI 预览母版**：`web/prototypes/jianshi2-v1/index.html`（已核实仓库文件存在，页面 `<title>` 为「见势 2.0｜视觉设计预览 · 非生产环境」，包含内嵌 WebP 主视觉）。这是**见势自己的可视化单文件参考模板**，不是 Super-i 的源代码。后续改动要先对照其颜色、字号、卡片结构、留白、动效和响应式规则，再依 B0 主次定位和「一眼看懂」规则取舍。不得把这份预览直接当成已上线的完整业务功能，也不直接编辑正式生成物。

**禁止以“参考 Super-i”为由修改 B0 商业主次关系或直接复制第三方页面、图片、文字、商标与代码。**

## 1. 从 Super-i 借什么（功能交互机制，而非原样抄页面）

| Super-i 既有可参考设计 | 见势的具体采用方式 | 现在要不要做 |
|---|---|---|
| 内容中心分类 + 搜索 + 卡片列表 | **创业项目筛选 / 分类 / 图片与简明文字卡片**：优先项目，而非正文讲系统机制 | **P0** |
| 列表卡片 → 详情 → 后续动作 | **项目卡→研究详情→可以先验证什么**；必要的财报出处和风险放正文后部 | **P0** |
| 鲜明的品牌首屏、统一颜色、卡片层级 | 见势独立的石墨深色、蓝紫渐变、中文排版、统一卡片样式、操作反馈；英雄区必须短，不得压住项目 | **P0** |
| 需求大厅 / 人才大厅两个入口 | 「企业用 AI」独立入口，按真实业务问题展示方案；商机及人才页若未开放只留简洁事实说明 | **P1（先场景、后交易）** |
| 企业需求选择向导 | 人工验证后，将提问简化成问题、期望结果、预算/限制；眼下的本地草稿不得暗示线上发布 | **P1，先不开放申请** |
| 创作者作品图片 / 视频 + 详情 | 等真实授权的作品、人才和需求出现后，再建设展示/申请流程 | P2 |

## 2. 见势页面母版：把复杂藏到背后

### 首页：唯一主任务「找创业项目」

固定的可见优先次序：
1. 品牌/短一句：「找创业项目，看懂怎么赚钱」；主按钮「直接看项目」，次按钮「按方向找」。
2. 第一组正式项目卡：**做什么 / 谁使用 / 谁付钱 / 怎么赚钱 / 上手门槛 / 看详情**，不把非付费使用者误称买家。
3. 搜索 + 轻量分类：按业务领域和模式浏览**现有已审核内容**；没有结果时说「暂无符合条件的项目」，不能自动杜撰。
4. 企业 AI 业务入口：一句「企业用 AI，可以解决哪些实际问题？」，进入独立方案目录。
5. 页脚或「更多」：商机、人才、学院及尚未开放的频道，仅说明现状，不罗列未来功能长篇计划。

不能用概念主视觉、用户规模数字、证据层级解释、英文字段、满屏按钮把真实项目挤出首屏。主导航可做视觉合并，但**原五模块和公开 URL 必须保留有效，不得直接删除路由**。

### 项目列表：一眼能比较

**统一卡片字段**：项目名称、简短是什么、谁真正付钱、怎么收费、能力/成本门槛、必要的一句话风险、进入详情。图片优先用合法来源可展示的真实项目/适当原创插画，不允许用虚构「成功创业现场」替代证据。

筛选使用直白名称如「电商」「网站工具」「内容生意」「服务类」，排序用「资料更完整」「还需核实」等普通话；不展示 L1/L4、OPP、工程版本编号。**排序不等于盈利能力或推荐购买。**

### 项目详情：先答案，再证明

第一页内容：
- 这是做什么的？／谁用、谁付钱？／怎么收费？
- 有什么门槛？／不适合谁？／如果想试，第一步是什么？
- 风险一句话：「这是历史案例，不代表你做也能赚钱」。

深层可展开内容：公开资料时点、官方或财报链接、具体疑点、详细成本与创业验证工作单。保持审计证据链接可见，不删真实风险或版权、安全说明。

### 企业 AI 方案：以问题开头

先问「你希望 AI 帮你做什么？」呈现四个**静态**业务场景；单卡显示适用商家、能解决的实际问题、预计交付类别（不是已经交付）、准备材料和关键风险。不把方案示例伪装成真实已签单服务。

### 商机、人才、学院

真正未开放的功能优先**简洁空状态 + 一个仍然可用的入口**，避免一页多段规划和工程说明；已经存在的纯本地模板可保留，但必须写清「内容不上传、不保存」「刷新将消失」。

## 3. 当前冗余清理顺序（冻结施工优先级）

| 优先级 | 要清理的东西 | 不做什么 |
|---|---|---|
| P0 | 创业者首页、/projects/、/discover/、/research/、案例详情的重复标题、证明口径和冗长段落；增强搜和比 | 不重新开发第二套研究引擎 |
| P1 | /solutions/ 四个方案：过多流程分段和内部英文名称，先给业务结果 | 不将企业业务提升成首页主业务 |
| P2 | /marketplace/、/talent/、/academy/：重叠的未开放说明、长篇规划、缺乏真实内容的入口 | 不开放账号、支付、撮合或虚构供需 |
| 独立门禁 | 390px / 1440px 实际浏览器截图、按钮导航、手机交互、至少 5 名真实创业者理解测试 | 不用 CI 或 AI 自评冒充真人验收 |

## 4. 每次 UI 施工必须按此执行

1. 先写一个真实用户任务（例如「3 秒内找到一个网站工具类项目并看清谁付钱」），写出「本次删减的冗余」，不得为了凑 PR 增加新页面。
2. 指明复用本文件哪一种**成熟交互模式**，B0 业务主次关系保持不变。
3. 一次只整理一个主要页面流（例如首页→项目卡→详情），保证旧 URL 可用、源数据不污染。
4. 验收至少包括：业务信息先出现、没有内部技术标签、来源与收费方准确、旧入口不失效；CI、实际页面内容、真实浏览器分别记录。
5. 真实客户/付费/发布能力未验证，**只能标注未开放**；不能编造业务业绩、效果、已成交服务。
6. 未经需求验证，默认不做新账号、CMS、Cloudflare 配置、服务商评级、竞标和支付。生产零写入、P4.41 私有采集四步骤仍按原规则。

**本文件冻结的是已批准商业逻辑下的 UI 模板应用方式，不代表已完成本文件所列剩余页面改造、实机测试、真实用户研究或交易上线。**
