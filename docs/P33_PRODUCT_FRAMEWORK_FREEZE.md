# P3.3 见势产品框架 V1 冻结

日期：2026-10-07
状态：FROZEN_V1
适用阶段：产品验证期 → 注册产品化前置设计
上位原则：质量优先、证据优先、中文用户优先、来源双赢、未授权数据 fail-closed

## 1. 一句话定位

**见势是面向中国个人创业者与内容创作者的商业机会发现与决策平台。**

见势持续扫描真实商业、产品、技术与市场信号，把分散的信息加工为：
- 值得研究的项目机会
- 可比较的项目评分
- 可执行的创业判断
- 可持续跟踪的机会变化
- 可用于内容创作的话题与案例

前台不以“海外资讯”作为产品叙事。全球来源是见势的数据供应链，不是用户购买见势的理由。

用户购买的是：**更快发现机会、更少浪费时间、更有依据地决定做什么。**

## 2. 产品不是什么

见势 V1 明确不做：
1. 不是资讯搬运站，不以翻译国外新闻、罗列海外动态为核心价值。
2. 不是 Acquire.com 的中文镜像，不复制完整 listing，不承接交易，不做交易中介。
3. 不是项目百科，不追求“收录越多越好”，质量和可行动性优先。
4. 不是单一热度榜，GitHub Star、产品点赞或社交讨论不能直接等于商业机会。
5. 不是收益承诺工具，评分是机会研究，不代表收入或成功概率。
6. 不是纯创投数据库，融资热度不等于个人创业机会。
7. 不是现阶段的个性化推荐系统，验证期先证明通用机会发现价值。
8. 不是靠故意切碎基础信息制造注册焦虑的付费墙产品。

## 3. 核心用户

### 3.1 第一核心用户：个人创业者 / 一人公司 / 小团队

用户任务：
- 找一个值得做的项目
- 找副业或第二增长曲线
- 找可复制、可本地化或可出海的商业模式
- 判断热点有没有真实商业价值
- 找真实案例验证想法
- 缩短“找方向 → 验证方向”的时间

详情页必须回答：
- 这个项目是什么？
- 谁愿意付钱？
- 为什么现在值得关注？
- 有没有真实商业证据？
- 一个人能不能做？
- 应该先验证什么？
- 最大风险是什么？
- 应该继续研究，还是放弃？

### 3.2 第二核心用户：自媒体 / 商业内容创作者

用户任务：
- 找值得讲的新话题
- 找真实案例、数据和反差
- 提前发现正在起势的方向
- 避免只追热点、没有商业深度

### 3.3 暂不作为第一阶段核心用户

专业 PE/VC、企业并购团队、券商投行、大企业战略部门、需要交易撮合的买卖双方。未来可以扩展，但不能反向把见势做成专业 M&A 工具。

## 4. 核心价值闭环

产品闭环：

发现 → 筛选 → 证据交叉 → 评分 → 项目判断 → 收藏/跟踪/推荐 → 行动或内容创作

后台闭环：

公开/授权来源 → 标准化 → Evidence Class → Opportunity Engine → 四维评分 → 编辑解释层 → 用户可消费的机会产品

冻结原则：**数据源不是产品；Opportunity 才是产品。**

单个 listing、repo、新闻、榜单只能成为证据，不能直接成为见势推荐项目。

## 5. 五类核心实体

### Opportunity｜机会
第一核心实体。表示用户可以研究、验证、进入或围绕其创业的商业方向。

### Evidence｜证据
证明 Opportunity 为什么值得关注。继续沿用：
- TECHNICAL_SUPPLY
- COMMERCIAL_PROOF
- DEMAND_SIGNAL
- DISTRIBUTION_SIGNAL
- OTHER

未来可新增 CAPITAL_SIGNAL，但必须先定义 Evidence Class 语义。

TECHNICAL_SUPPLY + COMMERCIAL_PROOF 继续作为当前 public_ready 的核心验证组合。

### Case｜案例
真实项目、商业样本或产品案例。Case 不等于 Opportunity。一个 Opportunity 可以关联多个 Case。Case 只在来源许可范围内展示，优先摘要、归因和原站跳转。

### Topic｜选题
面向创作者的消费层。Topic 必须来源于 Opportunity / Evidence / Case，不得脱离证据独立生成。

### Signal｜变化
包括新增证据、技术加速、新商业样本、首次多源验证、评分变化、退出活跃度变化。Signal 驱动今日推荐和未来提醒。

## 6. 四维评分继续冻结

OPP_V0.2 保留四维：
1. 趋势热度 HEAT
2. 内容价值 CONTENT
3. 可执行性 BUILD
4. 商业质量 BUSINESS

规则：
- 不用总分掩盖四维差异。
- Overall Score 只用于排序，不是唯一判断。
- GitHub 热度不能替代商业证明。
- Sold 状态不能当成交价。
- Asking price 不能当成交价。
- 高质量来源也必须先通过合法使用 Gate。
- 中国创业者解释层不能直接修改底层证据评分。

前台增加更易懂的“见势结论”，建议只用三类：
- 值得深入研究
- 值得验证
- 持续观察

“值得深入研究”不等于投资建议或收益保证。

## 7. 前台叙事冻结

### 7.1 不以“海外”作为核心卖点

错误叙事：
- 国外最近出现了什么
- 海外 SaaS 正在发生什么
- 美国创业市场有什么新趋势

正确叙事：
- 今天有哪些项目值得研究？
- 哪些方向正在起势？
- 哪些商业模式出现了真实商业证据？
- 如果今天要做一个项目，先看什么？

来源国家/地区只在影响机会判断时显示。

### 7.2 来源放在哪里

来源应该出现在证据区、数据出处、原始案例、归因和“查看原始项目”，而不是占据产品标题和主要叙事。

## 8. 目标信息架构

### 8.1 一级导航
V1 目标：
- 发现机会
- 今日推荐
- 正在起势
- 内容选题
- 我的见势（未来注册）
- 搜索

现有路由兼容：
- /today/ → 今日推荐
- /rising/ → 正在起势
- /build/ → 逐步演进为“发现机会/值得做”
- /content/ → 内容选题
- /opportunity/<slug>/ → 机会详情
- /account/ → 我的见势

未来可增加 /opportunities/ 作为项目库主入口，但迁移前不破坏既有 URL。

### 8.2 首页只完成五件事
1. 5 秒内解释见势能帮什么。
2. 给出今天最值得看的机会。
3. 给出找项目 / 看趋势 / 找选题三个入口。
4. 建立可信度。
5. 引导进入项目详情。

### 8.3 首页目标结构

Hero：**发现下一个值得做的项目**

说明：见势持续扫描真实商业、产品与技术信号，帮你发现项目、判断机会、找到内容选题。

随后：
- 搜索 / 快速筛选
- 今日推荐 3–5 个机会
- 找项目 / 正在起势 / 找选题
- 已验证机会
- 近期变化
- 简化版判断方法
- 注册价值
- Footer

底层 GitHub repo 列表不再长期占据首页主模块，它属于证据层。

## 9. 项目库

“发现机会”是最重要浏览入口。

目标筛选器只能使用真实字段：
- 已验证 / 待验证
- SaaS / 电商 / 内容 / AI / 服务等类别
- 商业质量
- 可执行性
- 一人公司适配
- 推荐市场：国内 / 出海 / 两边
- 资金强度：低 / 中 / 高 / 未知
- MVP 难度：低 / 中 / 高 / 未知
- 更新时间
- 正在起势

没有可靠数据必须显示“未知”。

机会卡只回答：
- 这是什么
- 当前结论
- 四维评分摘要
- 为什么值得看
- 证据强度
- 是否有新变化

## 10. 项目详情页是核心产品

详情页冻结为六层。

### 第一层：决策摘要
项目名称、一句话说明、见势结论、四维评分、证据状态、最近变化、未来收藏/跟踪入口。

### 第二层：机会说明
解决什么问题、谁付钱、商业模式、为什么现在值得看、什么情况下不值得做。

### 第三层：商业验证
真实商业样本、来源、样本质量、允许展示的收入/利润/asking price 字段、仍未知的信息。

原则：优先展示聚合分析，原始案例只做有限摘要 + 来源 + 跳转。

### 第四层：执行判断
一人公司适配、国内/出海/两边、MVP 难度、资金强度、获客难度、可切入细分方向、最小验证动作、主要风险。

禁止自动编造成本、周期、收入数字。

### 第五层：内容机会
为什么值得讲、适合什么受众、可选角度、关键事实、相关案例、应避免的夸大表达。

Topic 是 Opportunity 的衍生视图，不建立孤立内容事实库。

### 第六层：证据与来源
技术证据、商业证据、来源、更新时间、数据口径、风险披露、原始链接（许可范围内）。

## 11. 公开与注册边界

商业项目保护不能靠“全部锁死”。

### 游客公开
至少可见：
- 机会名称
- 一句话说明
- 当前状态
- 四维评分
- 部分判断
- 证据数量/类型
- 更新时间
- 少量许可范围内的案例摘要

### 目标注册用户解锁
未来注册后解锁：
- 完整机会分析
- 执行判断
- 风险分析
- 细分切入方向
- 完整证据摘要
- 相关案例列表
- 创作者选题模块
- 收藏
- 观察清单
- 变化提醒

### 未来会员
深度报告、提前预警、高级筛选、周报/专题、个性化推荐、竞品监控、导出、AI 研究助手。全部后置。

### 绝对边界
注册登录不能扩大第三方数据许可。

最终展示范围始终等于：
**用户权限 ∩ 来源授权范围 ∩ 见势发布规则**

## 12. 防“项目泄露”设计

1. Opportunity 抽象层优先：公开商业方向，不镜像第三方 listing。
2. Case 摘要化：只展示许可字段。
3. 原站导流：深入看原始项目时跳回来源平台。
4. 深度分析未来注册解锁：保护的是见势自己的判断和结构化研究。
5. NDA、隐藏卖家身份、客户数据、完整 P&L 等不进入系统。
6. 该归因的仍明确归因。
7. 未获书面许可不声称官方合作。

## 13. 创业者与创作者是双视图，不是双产品

Entrepreneur View：
深入研究、收藏、加入观察、看案例、看最小验证路径。

Creator View：
查看选题、保存选题、看关键事实、看案例来源、看相关趋势。

两者共用同一 Opportunity、同一证据、同一评分，不复制事实。

## 14. 推荐原则

验证期先做非个性化高质量推荐。

可进入推荐：
- 已验证机会
- 新完成多源验证
- 证据增长明显
- 技术加速度明显且已有商业证据
- 可执行性较高
- 内容价值较高

禁止：
- 纯热门强推
- 单来源强推
- 因合作关系提高排名
- 因广告提高评分
- 因平台给数据就把 listing 当成见势推荐

个性化推荐后置。

## 15. 数据来源双赢原则

理想关系：

来源平台 → 合法授权的有限数据 → 见势中文筛选/评分/分析/教育 → 中国创业者 → 高意向点击 → 原始来源平台

见势负责发现、理解、比较和教育；来源平台保留完整项目与交易关系。

因此合作申请不是“给我数据库”，而是：

**允许见势在明确边界内引用有限公开字段、做聚合分析，并把用户导回原平台。**

## 16. 来源与外联优先级

数据质量等级与外联优先级分开。

当前面向个人创业者的外联目标顺序：
1. Acquire.com
2. Microns
3. Flippa
4. Quiet Light / StartupMKT
5. FE International

发送计划必须在本产品框架冻结完成后单独制定。

## 17. 用户路径冻结

创业者：
首页 → 找项目 → 筛选/推荐 → 机会卡 → 公开摘要 → 未来注册解锁完整研究 → 收藏/观察 → 回访看变化

创作者：
首页 → 找选题 → 选题榜 → 机会详情内容视图 → 未来注册解锁案例/关键事实/更多角度 → 保存

搜索进入：
搜索引擎/分享 → 公开机会页 → 看懂价值 → 未来注册解锁深度 → 收藏/继续浏览

来源导流：
机会详情 → 相关商业案例 → 查看原始项目 → 合作来源平台

## 18. 验证期核心指标

优先验证：
1. 首页 → 机会详情点击率
2. 详情页阅读深度
3. 是否继续浏览第二/第三个机会
4. 找项目 / 正在起势 / 内容选题入口使用分布
5. 原始来源 outbound CTR
6. 用户对“项目是否有用”的主动反馈
7. 未来注册解锁后的注册转化
8. 收藏/观察使用率
9. 7 日回访率
10. 创作者选题保存/使用率

## 19. 视觉与交互方向

目标不是复制 Acquire 的皮肤，而是达到同等级的信息组织：
- 信息层级清楚
- 搜索/筛选强
- 卡片可比较
- 详情页数据密度高但不拥挤
- CTA 明确
- 桌面适合研究，移动适合快速浏览
- 中文优先
- 少装饰、少噱头、少“AI 感”
- 更像专业机会数据库，不像资讯门户

首页减少过多方法论、大段技术解释和底层 repo 直接曝光。

## 20. 开发顺序冻结

A｜产品框架冻结（当前）
- 本文档
- 产品合同
- 不发送合作邮件

B｜前台信息架构重构
- 首页
- 项目库
- 详情页
- 内容选题视图
- 搜索/筛选
- 不要求 Auth 开放

C｜两个高质量样板
- 一个已验证机会
- 一个仍观察的高热方向

D｜合作申请
- 按冻结定位重写合作意向
- Acquire / Microns / Flippa 优先
- 重点：有限字段、归因、导流、非镜像

E｜注册产品化
验证后再开放 Auth、完整分析解锁、收藏、观察、提醒。

F｜个性化与会员
后置。

## 21. 冻结规则

- PRODUCT_CATEGORY = 商业机会发现与决策平台
- PRIMARY_USER = 中国个人创业者
- SECONDARY_USER = 内容创作者
- FRONTEND_OVERSEAS_NARRATIVE = OFF
- OPPORTUNITY_IS_PRODUCT = TRUE
- RAW_SOURCE_IS_PRODUCT = FALSE
- FOUR_SCORE_MODEL = OPP_V0.2_UNCHANGED
- PUBLIC_READY_GATE = UNCHANGED
- SOURCE_POLICY_FAIL_CLOSED = TRUE
- FULL_LISTING_MIRROR = FORBIDDEN
- PARTNER_REFERRAL_MODEL = PREFERRED
- REGISTERED_ANALYSIS_MODEL = TARGET
- PERSONALIZATION = DEFERRED
- CHINA_PRIVACY_INFRA = DEFERRED
- PARTNERSHIP_OUTREACH_BEFORE_FREEZE = FORBIDDEN

任何后续功能若与上述规则冲突，需要重新开产品决策，不得静默修改。
