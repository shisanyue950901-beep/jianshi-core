# 见势 P4.23｜项目级商业证据档案（2026-10-09）

## 为什么做
P4.22 解释的是“某个商业方向是否有技术＋商业两类证据”；但不能把这类聚合记录绑定到某个具名公司。用户需要看到每个具体项目的“已有哪种事实支持／哪些指标没有证实”。

## 本轮产品交付
- 在公有页面 /projects/ 提供 **20 个独立项目档案**的索引，点击进入 /projects/<项目id>/ 。
- 每个档案提供五部分：业务说明、第一方可核对的产品事实与收费机制、日常经营和成本的编辑分析、实际交易与利润的缺口、下一步应当核查的内容。
- 四状态字段：产品／服务「有官方依据」，收费机制「有公开说明」，真实交易／客户「待独立核实」，利润／经营成果「待独立核实」。
- 两种最重要的第三方证据：Easlo 有 Notion 官方创作者页支持创作者关系；Louise Lennox 有 Amazon 官方过往采访支持使用 KDP 的历史经历。**两者都不证明当前收入。**
- 每个项目保留来自 P4.12C、P4.13、P4.15 的第一方来源链接：官网主页、产品/定价页面，且明确资料记录日期与非实时限制。具名项目未核验销量、真实净利、客户或需求，因此这四项不能显示成已通过。
- P4.22 行业方向界面增加「进入具名项目档案」导航；P4.21 首页主菜单、项目详情页增加项目级档案入口。

## 事实和权利边界
- 严禁将行业匿名交易市场的挂牌营收中位数当作某个具名公司的经营数据。
- 不提原始行业挂牌来源、记录编号、供应商名称、盈利数字、隐私业务 URL 或内部采集方法。对外链接只允许 HTTPS，不携带用户名或密码。
- “收费机制有公开说明”只意味着官网公开商品、定价或服务机制；不意味着发生任何交易。
- 研究的日期为资料记录日期，而非代表访问时已重新核对所有 20 个页面。
- 产品的经营成本与日常步骤为编辑分析，不是企业内部资料或 audited accounting。
- 一人公司／FBA／KDP 等类别属于编辑归类，不能推断相应品牌实际运营团队、Amazon FBA 使用情况或利润。
- 如需项目级「经营验证通过」必须另外获取独立且许可充分的财务、交易或客户资料，并建立逐条可追溯事实链；目前为 **0/20 已独立验证财务**。

## 数据与构建
- 单一数据来源：P4.13 JSON 10条、P4.15 JSON 8条，加 P4.12E 原 2 条经批准的第一方记录。
- 运行 `scripts/release/p423_build_project_proofs.py` 生成 `web/dist/projects/index.html` 和 20 个 `projects/<slug>/index.html`；通过既有 p412 public-only 构建嵌入发布流程。
- 不发布任何 `config/` `docs/` 或源文件到线上；公开项目页直接静态部署且无额外外部 API 查询/计费。
- sitemap 收录 /projects/ 和 20 个独立详情页；首页仍为 8 张 3D WebP，主 HTML 严格小于 260000 bytes。
- 不能更改 Cloudflare Pages 配置、Supabase Production/Edge/Cron/RLS、历史 PR #52；不调用 TinyFish 付费浏览器。

## 验收
- 新 21 页实际生成，项目 id 唯一，官网/核对依据均 HTTPS。
- CI 全套测试 + 静态安全扫描 PASS，检查每页“未核实”和“不能将行业证据套到具体企业”口径。
- sitemap 期望条目为 24：首页、隐私、P4.22 证据、P4.23 项目索引＋20 项目详情。
- CDN 真机视觉和第三方官网今日实际可达状态单独标记待验收，不把 CI 通过写成真人视觉通过。
