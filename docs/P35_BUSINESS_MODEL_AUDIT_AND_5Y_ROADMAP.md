# P3.5 见势商业模式审计与五年演进架构

日期：2026-10-07
状态：STRATEGY_FREEZE_CANDIDATE
前置：P3.3 产品框架已冻结，P3.4 合作外联计划已冻结

## 1. 执行结论

见势长期路线成立，但必须按“情报驱动的精选托管型市场（Intelligence-led Managed Marketplace）”演进，而不是直接做开放式 Agent 商店、项目交易市场或通用外包平台。

建议长期闭环：

机会发现
→ 注册与持续使用
→ 结构化咨询
→ 真实需求聚类
→ 创业者/服务商供给
→ 企业问题匹配
→ 精选方案
→ 托管交付
→ 成交/服务费
→ 交付结果数据反哺机会判断

商业上最关键的判断：

1. C 端负责增长、意图数据和供给形成。
2. B 端企业解决方案应成为长期主要收入。
3. 咨询是需求发现工具，不应演化成无限定制外包。
4. Marketplace 必须从真实人工撮合长出来，不能先造空市场。
5. Agent 只是解决方案形态之一，不是见势的终局品类。
6. 真正的护城河不是海外公开数据，而是“需求—方案—成交—交付结果”的闭环数据。

## 2. 外部商业基准审计

### 2.1 企业 AI Marketplace

Microsoft Marketplace 已经把企业 AI 应用和 Agent 做成“发现、比较、试用、购买、部署”的采购链路，并强调可信合作伙伴、清晰定价、试用、支付与部署。

Salesforce AgentExchange 进一步把企业 Agent 的“发现、购买、激活、管理”做成一体化入口。

启示：
- 企业不会长期为“Agent 文件”付费，而会为“可采购、可部署、可管理的业务结果”付费。
- 见势如果只做 Agent 上架，会直接进入巨头已占据的红海。
- 见势应该服务“中国中小企业具体问题”，并把 Agent、SaaS、自动化、服务商都抽象为 Solution。

### 2.2 自由职业 / 企业服务平台

Upwork 证明“匹配 + 合同 + 支付 + 平台服务费”的模式长期成立。

Contra 证明不一定要向供给端抽佣；也可以让供给端免费，通过企业侧合同费、工具订阅和工作流收费来建立生态。

中国猪八戒已经覆盖企业服务、技术开发、AI、营销等大量类别，并具备任务发布、服务商、担保交易、验收、平台服务费体系。

启示：
- “中国通用企业服务市场”已经是成熟红海。
- 见势不能正面复制猪八戒。
- 见势必须坚持“机会情报 → 精选解决方案 → 标准化企业问题”的窄切口。

### 2.3 Agent 创建与分发

腾讯元器已经提供零代码 Agent 创建、发布、广场分发、公众号/企微等生态集成以及企业级 API 路径。

启示：
- 创建 Agent 本身会越来越商品化。
- “有多少 Agent”不是壁垒。
- “哪个方案能解决哪个企业问题、实际效果如何、谁能交付”才有商业价值。

### 2.4 商业项目交易

Acquire.com 当前采用订阅 + closing fee，并提供筛选、推荐、卖家/买家验证、交易支持、托管合作等完整市场服务。

启示：
- 交易平台的收费来自“信任、匹配、流程与成交”，不是来自 listing 本身。
- 见势未来若做项目/解决方案交易，也必须先建立信任层，不能只开放上传和支付按钮。

   - 提醒
   - 用户数据隔离
   - Auth 仍保持 fail-closed

5. 长期可形成数据飞轮
   - 当前：公开商业与技术数据
   - 未来：用户意图、咨询、供给、企业需求、交付结果

### 当前短板

1. 没有真实 PMF 数据。
2. 注册用户尚未启动。

结论：
见势当前是 Opportunity Intelligence MVP，不是 Marketplace MVP。

## 4. 终局商业定位

长期北极星：

见势是连接商业机会、创业者能力与企业真实需求的精选解决方案平台。

对个人创业者：
- 找项目
- 判断项目
- 获得咨询
- 做出产品
- 展示能力
- 获得客户
- 实现变现

对内容创作者：
- 找选题
- 找真实案例
- 找商业证据
- 形成内容分发
- 为见势带来低成本用户增长

对企业：
- 提交真实业务问题
- 获得需求诊断
- 找到经过验证的解决方案/团队
- 购买、实施、验收、持续维护

见势负责：
- 机会识别
- 需求结构化
- 方案筛选
- 信任与验证
- 匹配
- 项目管理
- 交付质量
- 结果数据沉淀

## 5. 商业模型分层

### L1 免费机会发现

面向所有访客：
- 项目发现
- 基础评分
- 今日推荐
- 正在起势
- 内容选题
- 部分证据

作用：增长、SEO、传播、建立信任。

### L2 注册工作区

注册不是目的，而是持续使用身份层。

注册后逐步提供：
- 完整分析
- 收藏
- 观察
- 变化提醒
- 咨询入口
- 项目研究记录
- 后续推荐

规则：
必须先让游客看见价值，再要求注册。

### L3 结构化创业咨询

前期咨询可以人工参与，但必须产品化。

咨询入口不采用“你想问什么都可以”的无限开放模式，而是结构化：
- 你想解决什么问题？
- 你有哪些能力/资源？
- 预算/时间/行业约束？
- 想做国内还是出海？
- 你在找方向、验证、产品还是获客？

输出固定为：
- 推荐机会
- 不推荐方向
- 证据
- 最小验证动作
- 风险
- 下一步

咨询数据必须进入匿名化需求分类，而不能只存在聊天记录里。

### L4 精选 Solution 供给

当咨询中持续出现“我已经做了产品/Agent/服务，如何变现”时才开启。

Solution 可以是：
- Agent
- SaaS
- 自动化工作流
- 数据产品
- API
- 插件
- 标准化服务
- 行业方案

不是自由上架。

进入 Solution 库前至少审核：
- 功能 Demo
- 目标客户
- 解决的问题
- 交付方式
- 定价逻辑
- 维护能力
- 所需数据权限
- 知识产权声明
- 已有案例/测试结果
- 服务边界

### L5 企业需求与诊断

企业入口应是：

“告诉见势你的业务问题”

而不是：

“选一个 Agent”

企业需求模板：
- 当前流程
- 最痛的问题
- 基线成本/耗时（企业自报）
- 使用系统
- 数据敏感程度
- 预算区间
- 时间要求
- 成功标准

见势先做需求诊断，再决定：
- 现成 Solution
- 组合 Solution
- 服务商实施
- 不适合自动化

### L6 Managed Marketplace

只有真实需求与供给都形成后才进入。

初期采用：
人工精选 + 人工匹配 + 标准合同/验收模板 + 第三方支付。

不做：
- 开放式无限上架
- 自建托管资金
- 自动放款
- 大规模争议仲裁系统

后期达到交易密度后再平台化。

## 6. 收入模型审计

### 第一阶段收入
不是主要目标，但可测试：
- 深度创业咨询
- 专题研究
- 高级机会报告

作用：验证用户付费意愿。

### 第二阶段收入
- 企业需求诊断费
- 解决方案评估费
- 企业 PoC / 实施服务费

作用：验证企业是否愿意为结果付费。

### 第三阶段收入
- 项目撮合服务费
- 托管交付服务费
- 成交佣金
- 持续运维费

### 第四阶段收入
- 企业订阅
- Provider 工具/认证
- 高级采购工作流
- 数据与 API
- 大客户定制协议

### 收入质量排序

长期优先：
1. 企业持续运维 / 订阅
2. 企业解决方案服务费
3. Managed Marketplace 服务费
4. 成交佣金
5. 个人咨询
6. 个人会员
7. 广告

广告不应成为核心商业模式。

## 7. 关于抽佣的客观判断

不要现在冻结固定抽佣比例。

市场已经证明多种模式都能成立：
- Upwork：客户端 Marketplace Fee
- Contra：供给端 0 佣金，企业侧合同费/工具收费
- Acquire：卖方订阅 + 6%–8% closing fee
- 猪八戒：平台服务费、流量服务费、协同分账

因此见势未来收费应按平台实际创造的价值分层：

- 仅导流：低收费或不收费
- 需求诊断 + 匹配：服务费
- 管理项目：更高服务费
- 承担验收/交付协调：Managed Service Fee
- 软件持续运行：订阅/运维费

平台承担的责任越大，收费比例才应越高。

## 8. 最重要的战略防线

### 禁止 1：通用 Agent 商店
理由：供给极易泛滥，腾讯元器、微软、Salesforce 等已有规模优势。

### 禁止 2：通用外包平台
理由：中国已有猪八戒等成熟玩家，正面竞争没有优势。

### 禁止 3：无限定制咨询公司
理由：无法规模化，会吞掉团队所有资源。

### 禁止 4：过早做交易基础设施
理由：支付、合同、发票、争议、退款、身份验证、知识产权都会指数级增加复杂度。

### 禁止 5：把注册数当 PMF
注册是 Identity，不是商业价值。

### 禁止 6：为了 Marketplace 人为制造供给
没有真实企业需求前，不批量邀请 Agent/开发者上架。

## 9. 见势真正的护城河阶梯

Level 0：公开国外信息
几乎没有壁垒。

Level 1：数据清洗与评分
有工程壁垒，但可复制。

Level 2：用户行为
知道用户收藏、关注、持续研究什么。

Level 3：结构化咨询数据
知道中国创业者真正想做什么、卡在哪里。

Level 4：Solution 实际能力
知道哪些方案能交付，谁靠谱。

Level 5：企业真实需求
知道企业愿意为什么问题付钱。

Level 6：成交与交付结果
知道：
- 什么方案成交
- 成交价格区间
- 实施周期
- 是否验收
- 是否复购
- 哪些服务商稳定

Level 5–6 才是长期无法通过抓公开网站复制的数据资产。

## 10. 创作者角色审计

内容创作者不应成为主要收入对象。

更好的战略定位：
- 第二核心使用者
- 低成本分发网络
- 趋势传播者
- 项目案例放大器

长期可以提供：
- 选题库
- 数据卡片
- 可引用图表
- 分享链接
- 来源引用
- 创作者工作区

如果创作者使用见势生成内容，并持续把新用户带回平台，就形成：
数据 → 选题 → 内容 → 用户 → 行为数据 → 更好机会推荐 的分发飞轮。

## 11. 注册策略

用户提出“先要注册用户”的方向正确，但需改为：

先建立注册身份层，不以强制注册墙为第一目标。

推荐：
- 公开：项目概要、评分、基本证据
- 注册：完整分析、收藏、观察、咨询、选题深度
- 后续付费：深度咨询/报告/高级工具

Auth 只有在现有 8 个 Launch Gate 全部 PASS 后开放。

中国个人信息专项基础设施可以后置，但正式开放 Auth 前仍必须有最低限度的隐私说明、数据用途说明和删除能力；不能因“验证阶段”而完全跳过。

## 12. 五年演进路线

日历不是硬约束，阶段 Gate 高于年份。

### 第 1 年：Opportunity Intelligence + 用户验证

目标：
- 前台产品化
- 注册工作区
- 结构化咨询
- 商业数据源扩展
- 机会推荐质量提高
- 创作者选题工具

不做：
- 开放 Marketplace
- 自建支付托管
- 大量 Provider 招募

需要证明：
- 用户愿意持续回来
- 用户愿意注册
- 用户愿意提交咨询
- 出现重复需求主题

### 第 2 年：咨询产品化 + Curated Supply

目标：
- 把高频咨询问题做成标准化研究路径
- 允许少量创业者提交 Solution
- 建立 Demo / 能力 / 交付审核
- 形成 2–3 个重复出现的企业问题类别
- 开始企业需求访谈和小规模 PoC

### 第 3 年：Managed B2B Matching

目标：
- 企业可以提交需求
- 见势人工诊断
- 精选 Solution 匹配
- 标准 SOW
- 第三方支付
- 里程碑验收
- 服务费模型

只有完成真实成交和交付，才考虑 Marketplace 产品化。

### 第 4 年：托管型 Marketplace

目标：
- Provider 信誉体系
- Solution 评价与交付数据
- 企业采购工作流
- 报价/合同/验收数字化
- 复购
- 运维订阅
- 企业账号与团队协作

### 第 5 年：平台网络效应

目标：
- 更开放但仍受控的 Solution 市场
- 企业自助采购
- 推荐与匹配算法
- 行业解决方案库
- 数据产品/API
- 合作生态
- 高质量跨境项目与服务连接

终局仍不是“最多 Agent”，而是：
最高质量的机会—需求—解决方案—交付网络。

## 13. 阶段 Gate

### Gate A：从机会平台进入咨询产品化

最低证明目标（用于决策，不是收入预测）：
- 至少形成一批真实注册用户
- 至少 20 个结构化咨询/需求样本
- 至少出现 3 个重复问题簇
- 用户会主动收藏/观察并回访
- 有用户明确愿意为更深研究或咨询付费

若没有重复需求，不进入 Solution 市场。

### Gate B：从咨询进入供给库

至少：
- 3 个重复问题簇可以定义明确 Solution
- 至少 10 个候选方案/服务者
- 至少 5 个方案通过人工 Demo 和交付能力审核
- 有真实用户表达“希望有人直接帮我做”

### Gate C：从供给库进入企业试点

至少：
- 10 次合格企业需求访谈
- 3 个愿意付费的 PoC/试点
- 至少 2 个项目完成验收
- 项目范围可以标准化，而不是每单完全重做

### Gate D：从人工撮合进入 Marketplace

至少：
- 已完成多笔真实付费项目
- 出现复购或转介绍
- 有可复用的合同/报价/验收结构
- 平台服务费覆盖人工协调成本
- 争议/失败模式已经被识别并可控制

若没有这些证据，继续 Managed Service，不开发开放交易市场。

## 14. 关键失败信号与转向规则

### 信号 1
用户大量浏览但不收藏、不咨询、不回访。
处理：回到机会质量和详情页，不扩 Marketplace。

### 信号 2
咨询很多，但每个需求完全不同。
处理：选择一个高重复垂直场景，而不是继续扩大类别。

### 信号 3
创业者愿意提交 Solution，但没有企业需求。
处理：停止招募供给，把资源转向企业访谈与需求侧。

### 信号 4
企业愿意咨询，但不愿意付费。
处理：验证问题是否足够痛、ROI 是否可量化，而不是继续加功能。

### 信号 5
企业愿意付费，但项目永远高度定制。
处理：可保留高价值服务业务，但不要假装它已经是可规模 Marketplace。

### 信号 6
成交很多，但交付失败/返工严重。
处理：提高 Solution/Provider Gate，而不是扩大流量。

## 15. 未来数据模型方向

当前 Opportunity / Evidence 继续作为发现层。

未来新增概念（未授权实施）：
- ConsultationRequest
- NeedCluster
- Solution
- Provider
- EnterpriseNeed
- Match
- Proposal
- DeliveryMilestone
- Acceptance
- Outcome
- Reputation

关键关系：

Opportunity
→ ConsultationRequest
→ NeedCluster
→ Solution
→ EnterpriseNeed
→ Match
→ Delivery
→ Outcome
→ Opportunity Intelligence

这会形成真正的数据闭环。

## 16. 企业解决方案必须“问题优先”

企业端不应出现：
“购买 Agent”

首页应该问：
“你最想解决哪个业务问题？”

例如：
- 客服成本
- 销售线索
- 内容生产
- 报表与数据整理
- 招聘筛选
- 电商运营
- 内部知识检索

然后才匹配 Agent / SaaS / 自动化 / 人工服务。

这可以避免把技术形态当需求。
