# F2.1-00｜G0 现状审计、需求与页面清单

状态：G0_BASELINE_FREEZE；日期：2026-10-11。性质：工程实施合同，不等同于功能已上线。
依据：F1 视觉冻结、P4.45 单首页、P4.46 八个内容页、P4.48 两个本地草稿工具及私有 V2 基线。

## A. 真实现状（核验）

- GitHub 主分支已具有独立发布器 scripts/release/p412_build_public.py；Cloudflare 面向 web/dist 静态快照，web/build.py 还存在历史构建能力，不能将其产出的老版界面重新拼回正式首页。
- 生产主页采用单一 JIANSHI 2.0 五入口；旧版 3D ring/灯箱/旧归档不得混入。
- 具名企业研究 Carrd、Plausible、NerdWallet 为历史证据收录，并非个人可以复制其收入；另有 6 类独立匿名行业研究。
- 企业解决方案 4 个详页、独立方案目录、商机说明、人才准备、学院规划，共 8 个内容页；/marketplace/brief/ 和 /talent/portfolio/ 是仅浏览器本地草稿，**非真实发布**。
- 本轮只读数据库复核：staging 6/6 撮合表 FORCE RLS；staging 的 account_auth / v2_matchmaking 均 false；生产 account_auth false、无 jianshi_v2 schema 和撮合标记。不得把数据库存在误报成业务已开放。
- 既有定时工作流仅 UTC 00:55 / 06:55 / 12:55 / 18:55；HN≤7、RSS≤1、GitHub REST≤2，不得随 UI 开发改变。只有 event=schedule 是自然调度验收，push/dispatch 不能替代。
- 目前仓库没有可安全投入生产的统一内容 CMS 或认证的双边撮合 API；未完成帐号 E2E 和管理员授权矩阵。

## C. 角色、非目标和依赖

- 游客只看审核后的公共摘要；个人用户可以收藏和学习；创作者可在权限开放后建设本人资料；企业负责人/成员受企业组织隔离；审核员和管理员依据可信服务端角色授权。
- 非目标：用户资金托管、自动分账、虚构课程或订单、未授权资料抓取、课程支付、自动审批。
- 课程与市场录入均依赖后台 CMS、安全登录与授权；不得以页面上的按钮替代该能力。
- 任何业务真实上线必须先完成原 Auth Gate 八项 E2E、跨用户读写隔离和企业组织边界测试。

## D. 冻结范围与 G0 验收

G0-1：唯一正式构建器与仓库发布文件关联清楚，旧页从首页隔离。
G0-2：静态站、私有企业数据、课程媒体、审计数据分四区；schema、API、存储不得互相越权。
G0-3：每个 P0 页面有路径、角色、输入、输出、状态、空状态和内容负责人。
G0-4：冻结已上线/演示/未来规划三种标识，不将草稿工具称为“交易已上线”。
G0-5：每个变更列出允许修改路径与明确禁止目录；未通过安全验收不得合并生产功能开关。
