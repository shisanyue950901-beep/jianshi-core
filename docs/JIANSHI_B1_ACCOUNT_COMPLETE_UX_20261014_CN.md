# 见势 B1｜正规邮箱账户注册体验与发布边界（2026-10-14）

## 本次完成的可执行源码

- 邮箱＋密码：注册、登录、退出；Supabase Auth 提供会话和密码存储机制，不建立自己的密码库。
- 注册：设置和确认密码（8–128 位）；输入时提示密码长度和组合；显示/隐藏密码；必须勾选并可打开现有隐私政策；请求邮箱确认后可重发，客户端 60 秒邮件冷却。
- 登录：注册/登录原地切换；常规密码登录；身份出错时不泄露是否注册，避免账号枚举。
- 忘记密码：通过注册邮箱申请重置邮件，返回页面设置新密码；已登录账户支持修改密码和安全退出。
- 保留备选一次性邮箱链接；登录后继续保留个人收藏、观察清单、提醒和清空个人研究数据功能。
- 统一注册双栏原创蓝紫品牌视觉，含手机 390px、桌面 1440px 无横向溢出、焦点操作、易读的验证状态与密码提示。
- 修正之前的一个实质缺陷：`[data-auth-panel]` 和 `[data-auth-switch]` 必须使用 `querySelectorAll`，不可用 `querySelector` 后直接 `forEach`。
- 注册预览页同步展示邮箱、密码、确认密码的设计，但依旧**没有可输入表单/提交/发信**。

## 不可混淆的三类验收

1. 源测试：渲染账户表单、隐私要求、Supabase Auth API、前端隔离和现有 8 项生产 Gate。
2. Chromium：真正点击网页的注册／登录切换、密码可见、密码提示、重复校验、模拟注册确认和重发、找回、模拟登录、模拟修改密码及退出；在隔离的 Mock Supabase ESM 上运行，**没有发出真实注册邮件或写入任何用户**。
3. 生产：SMTP、邮件域名/发件人、Supabase URL/Redirect URL、真实邮箱注册和回调、刷新/退出、AB 用户隔离、收藏观察提醒等，**尚未完成**，因此不能宣称线上注册已开放。

## 当前生产现实

生产 `account_auth` 继续关闭；`custom_smtp_configured=false` 等 8 项 Gate 为 false（经只读数据库核验）；公开 `/account/` 保持安全跳转，`/account/preview/` 仍只有无表单设计预览。不能绕过 SMTP 邮件确认以制造“注册成功”假象。

## 发布所需的实际外部配置

需要在生产 Supabase Authentication 中完成自定义 SMTP（具备已验证域名和发信账户的服务商），确认 Site URL 和精确 HTTPS 重定向 `https://jianshi-bua.pages.dev/account/`。随后用真实受控邮箱完成注册确认、登录与找回 E2E，再完成 A/B JWT 数据隔离、个人收藏／观察／提醒、刷新和退出、Security Advisor 复核，按原 SQL 管理入口设置 8 项 Gate PASS，然后启用构建侧意图并重新生成正式网站。

浏览器 Mock 验收永远不替代上述生产 E2E。不会储存密码到浏览器 localStorage 或添加未经用户确认的营销订阅；真正账号注销功能还需独立服务端身份核验与删除事务实现，不能用现有“清空收藏”假冒注销。
