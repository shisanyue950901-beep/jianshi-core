# P4.10｜公开数据渠道保护与中文案例展示

目标：全面修正 P4.9 不当公开展示第三方服务商、接口采集方式、原始挂牌标题、编号、精确逐条金额与原始分类的问题。

## 公开端约束

- 不显示供应商、接口地址、调用方式、原始标题、挂牌编号、原始分类；
- 技术仓库具体项目、仓库 URL、原始商业记录不出现在公开接口；
- 网页不能通过 CSS 隐藏实现数据脱敏；必须在服务端返回前字段白名单化；
- 研究汇总数据仍允许输出，案例逐条财务改为宽金额区间；
- 未收录在中文翻译字典的领域名称统一为“其他领域”，不能偷偷回退为英文；
- 业务类型与领域中文自动映射，无需人工逐条翻译；
- 公开研究接口设置 Cache-Control no-store；不再输出内部异常详情。

## 风险边界

原始网页曾公开的源名称、原始标题和编号已经有过外部访问机会。新部署只能阻止继续主动暴露，不能保证已被缓存或第三方抓取的旧内容消失；需要后续检查 CDN / 搜索引擎缓存并清理历史资产泄漏面。

## 当前工程变化

- Supabase public-feed：research 响应白名单、中文项目类别、中文匿名案例、金额分组与中文领域
- Supabase public-feed：detail 不返回 raw github/marketplace，home 不返回原始技术仓库发现列表
- web/build.py：首页/研究库/详情/趋势页不输出供应商、接口方式、来源时间、原始标题或编号
- web/static/styles.css：三列统计条、匿名中文表格
- CI：自动扫描静态构建产物中的敏感来源标记

不改变数据库底层采集链、研究规则、OPP_V0.2、Auth Gates、PR52 或生产交易/写入逻辑。
