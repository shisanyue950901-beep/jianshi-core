## 二、实际交互

- **内容队列**：仅两个合成样稿（AI 自动化方案、AIGC 课程大纲），可按关键词和状态筛选；显示当前状态、版本、模拟事件计数。
- **身份模拟**：作者 A、作者 B、审核员 B、发布员 C、访客。模拟身份切换只验证动作可用性，**不是 Supabase 登录**、不能代替可信服务端权限。
- **草稿编辑**：标题、摘要、正文、事实核验和授权检查；必须为本人编辑、内容处于草稿并匹配当前版本；错误时不改变原文。
- **审核闭环**：草稿→待审核→批准→模拟发布→撤回；拒绝可重编，作者不能自审，非发布员不能发布。
- **素材版权**：许可未核实或扫描未通过时不能批准/发布；只修改合成状态，无实际文件上传、版权证书或杀毒扫描。
- **版本对比**：每次模拟状态或编辑变化留一版，支持旧版/新版对照，任何用户输入用 `textContent` 展示，不执行 HTML。
- **审核事件**：本地模拟动作、角色和版本号，不向正式站、Supabase 或日志传输内容。
- **模拟公开投影**：按字段白名单，仅包含类型、标题、摘要、类别、来源和版本，不包括正文、内部备注、素材原始记录、邮箱等。投影只是浏览器内存状态。

## 三、内容测试与阻断项

执行 `node --test tests/f21_g1f_model.test.cjs`，另由现有 Python 单元测试自动触发。包括：
1. 新打开时 2 个合成内容、0 公开案例、0 审核事件。
2. 作者 B 不能修改作者 A 内容，访客不能批准，不能提交额外未授权字段。
3. 旧版本的编辑被 `STALE_REVISION` 拒绝；任一非法字段使整次编辑回滚。
4. 未核实来源或授权的审核拒绝；版权不明、扫描待处理的审核拒绝。
5. 正常合成流程：拒绝→作者重编→双人审核→模拟发布→撤回，公开白名单不会出现私有字段。
6. 待审核后不可再直接修改正文，非法状态变化必须拒绝。
7. 所有合成事件不影响另一份记录，也不改变初始样本。

## 五、下一阶段 G1-G 的前置任务

优先完成独立 Auth 启动的剩余 E2E 条件和自定义 SMTP；然后仅用经过授权的合成测试账号，在 staging 连接已部署 `cms-staging-gateway`。调用真实 API 前必须独立做 JWT/session、跨账号隔离、并发 CAS、重复请求、审核和撤回的端到端测试。为真正管理员面板设置独立可信服务端接入和审计，不直接在静态浏览器加入 `service_role`。媒体私有存储与扫描机制要另列发布门禁。

### 需要项目负责人的后续输入

**当前不需要任何即时操作。** 准备真实登录 E2E 前才需要确认/配置自有域名的邮件发信服务及安全凭据（由用户在供应商控制台配置，绝不在聊天中发送密钥）；需要真实对外内容时提供已授权案例/作品/课程素材。没有这些材料时，本轮纯合成界面与流程开发可以继续进行。

**保护项：** 不更改 UTC 四个采集时槽、HN Algolia≤7、RSS≤1、GitHub REST≤2 次/日；不访问私有客户内容、不碰 production RLS 或用户注册。
