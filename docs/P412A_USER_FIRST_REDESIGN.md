# P4.12A｜见势面向真实用户的产品化重构

状态：DESIGN_REVIEW / NOT_RELEASED

## 为什么重构

现在线上首页和详情页把统计指标、数据口径、工程管理说明放到了用户最先看到的位置。用户真正关心的“这是什么生意、钱从哪里来、一般怎样运营”，反而靠后或缺失。

此次不重新设计为工程终端。产品身份冻结为：

> 见势是帮助中文用户发现、了解和研究海外商业模式与具体项目的信息平台。

“有真实案例的商业模式”不等于“已核实的独立项目”。六个首页入口目前是六种**业务类型**，不是六家独立公司，也不是 107 个经过逐一尽调的具体项目。

## UI 设计参考和改造边界

用户提供了 MotionSites.ai 上的一套黑色野生动物摄影档案提示词。设计沿用其：

- 深黑底色、轻质感边框、留白、衬线标题、克制文字；
- 有层次的中心空间构图；
- 缓和的元素入场、卡片悬停、页面切换；
- 画廊与信息阅读视图的双模式思考；
- 低动态偏好兼容及移动端降级。

**不照搬**：摄影师姓名、图像、影像 CDN、21 张摄影球体、不可跳过的视频、滚动锁定、原始提示词或它的界面文案。

原因：见势需要的是项目发现效率，不是摄影作品展示的沉浸体验。动效必须帮助用户辨别页面层级，不能挡住关键内容。

## 新信息架构

主导航：

1. 发现项目
2. 商业模式
3. 关于见势

避免把“趋势信号 / 数据口径 / 隐私策略 / 后台资产保护”作为最醒目的核心导航项。
隐私政策应保留可达，但放在页脚并清除暴露内部配置的措辞；非产品核心的旧趋势页保留兼容路径，但不在新首屏引流。

### 首页

首屏：用户价值陈述 + 单个主操作 + 轻量空间视觉。
项目展示：六种商业模式卡，每卡优先展示“做什么 / 怎么收费”，而不是先展示利润中位数。
内容说明：见势帮助用户了解四个问题——项目是什么、收入从哪里来、有哪些海外案例、哪些信息还需核实。

### 详情页

1. 这个项目在做什么
2. 收入从哪里来
3. 业务通常如何运作
4. 海外有哪些参考
5. 尚需核实哪些关键问题
6. 继续了解相关模式

**严格区分**业务普通知识、来源披露数据、见势编辑分析、未知事实。禁止按照模板自动捏造具体项目成本、人力、获客路径、团队规模或中国市场适配结论。

## 两个内容样板

- 数字产品：单次售卖、授权交付，与“所有数字产品都可自动赚取被动收入”区分。
- 亚马逊数字出版：图书销售和版税收入，与“某个观察到的出版商具体怎样经营”区分。

两个样板均先用商业模式基础知识解释，不把匿名聚合统计当成可核实企业档案。

## 后台/公开双边界

后台保留全部原始来源、项目标识、映射规则、运营口径、评分和审计字段。

公开产品只接受严格字段白名单：

```
business_model_title
business_summary
product_or_service
revenue_mechanism
general_business_process
approved_aggregated_evidence
clearly_labeled_unknowns
```

禁止公开供应商身份、采集方式、原始挂牌标题、编号、内部 URL 和业务源代码路径。公开页不得出现 “脱敏策略 / API / Epoch / OPP_V0.2 / 采集方式 / Gate”等工程标识。
