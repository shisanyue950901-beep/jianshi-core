# 见势 JIANSHI 2.0｜B0 双业务线定位与资源决策冻结（2026-10-13）

**性质：用户批准的战略优先级修订，NOT_PRODUCT_RELEASE；此前 P3.3、P3.5、F1、F2.1 的历史判断及工程安全门禁继续有效。**
本文件负责说明新旧决策的优先级，不允许通过「新战略」悄悄启用尚未测试的业务。

## 1. 现在卖的是什么

**唯一品牌主定位**：见势是面向中国个人创业者的「商业机会发现与决策平台」。
用户核心利益：发现有证据可核验的商业项目与业务方向 → 理解怎么盈利 → 判断研究价值、前提和风险 → 用较低成本验证想法。
品牌表达：**发现机会，让机会变成生意。**

**第二业务线**：见势企业服务（内部试验名称）——中小企业 AI 方案诊断、选型与落地效果验证。
最先服务：有具体业务痛点、采购负责人、可描述现状与试点约束，且没有成熟 AI 实施团队的中小企业；企业人数范围 10–100 人仅是初筛假设，不能当准入硬条件。
流程：具体问题 → 现状与约束 → 现成工具/不使用 AI/组合工作流/定制方案比较 → 小范围 PoC → 结果复核 → 是否进入持续服务。
第二业务线暂不成立正式自由交易市场、会员等级、佣金、无边界定制外包或资金托管。

### 与历史战略的关系

| 既有决策 | 现在怎么处理 |
|---|---|
| P3.3 个人创业者为第一核心用户，Opportunity 是产品 | **原样保留**；首屏、推荐、项目档案始终个人创业用户优先 |
| P3.5 「B 端未来为主要收入」 | 调整为**长期假设、需真实付费证据验证**，不得当成既成事实强行改变当前主线 |
| F1 五入口与内容、人才、学院长线 | 保留入口与内容，但商机大厅、正式入驻、课程上传仍为未上线，禁止虚构交易与用户 |
| G2-H.7 安全验证工程 | 完成成果保留，不继续无用户场景支持的云端配置扩张；所有上线门禁继续锁闭 |
| P4.41 来源采集与 OPP_V0.2 四维研究模型 | 严格保留，原授权、来源准入、证据等级与定时预算不能改变 |

> **关键约束**：B 端的收入潜力不能替代 C 端的用户价值；C 端的内容访问量也不能假装成 B 端的销售线索。各条业务线分别统计，不能混报。

## 2. 两条用户价值路径与导航优先级

**主线 A：发现机会**（当前 P0）
匿名访问 → 搜索或筛选已审核研究 → 机会说明及原始证据 → 真实商业案例与未知项 → 合理的下一步研究建议 → 意愿反馈/回访。
不强制注册，不把单来源的热度榜、原始挂牌或虚构的未来收益当成商业推荐。个人创业机会 **不局限于 AI**，可以包括工具、数字产品、电商、内容、服务以及经审核的行业方向。
第一屏应继续让用户在 5 秒内理解「找商业机会和研究项目」，**企业获客不成为新的全站 Hero**。

**次线 B：见势企业服务**（独立 P1，先人工验证）
独立 /solutions/ 入口 → 查看四类已有方向及真实许可的示例/练习 → 明确说明「现阶段人工试验，不保证节省成本/成交/供应商数量」→ 企业研究访谈（线下或单独授权受控渠道）→ 方案比较 → 人工试点。
未经授权，浏览器本地需求整理器不上传、创建订单或保存用户私人数据；不在公开站放上「提交后可接单」的虚假按钮。

**两边共用：** 合法来源、事实核查、内容质量、案例结构、成本及风险评估模板。
**两边不强行共用：** 客户注册漏斗、权限、企业联系信息、研究指标、计费系统。未获得明示同意，不得将个人创业行为数据拿去 B2B 营销。

## 3. 用五大板块的现有资产兑现战略

| 模块 | 当前可用底座 | 新的工作优先级 | 未来放行 Gate |
|---|---|---|---|
| 商业机会库 | 已审核案例、行业研究、公开内容发现、搜索/筛选、OPP 四维与证据层 | **P0：核心投入**；重做核心任务的易用性、样板质量、研究下一步 | 可核验证据 + 真人有效使用反馈 |
| 企业解决方案 | 四类公开静态方案与浏览器本地需求准备 | **P1：低成本试验**；完善场景问题、比较方法、PoC 验收示例 | 真实访谈、独立说明展示/交付状态 |
| 商机大厅 | 公开说明和纯本地草稿 | P2：冻结开放交易 | 企业认证、审核、授权和真实供需样本通过 |
| 人才与服务商 | 公开说明和纯本地作品草稿 | P2：人工核验最多数名试验候选，未验证不公开 | 资质/作品/权属审核，客户同意 |
| AIGC 学院 | 学习方向与练习内容 | P2：围绕创业所需能力设计低成本练习 | 有原创授课版权、教学与课程功能验收 |
| CMS/Auth/mTLS/数据库 | 隔离 E2E、Fail Closed 审计、登录预备架构 | P3：维持安全，用户功能有明确需求才继续 | 原有独立 Auth 及环境安全上线门禁，不得绕过 |

## 4. 90 天资源建议（是实验预算，不是 KPI 承诺）

以工作量占比暂定：**65% 主线机会发现、25% 企业服务验证、10% 必要工程维护**。如果日常有阻断性安全漏洞，应临时调整并留下原因。不能因为「B 端商业价值可能更高」就默默侵占主线研发。

**第 1–30 天：** 
- 主线：针对创业者的首页 5 秒可懂性 / 筛选任务 / 详情证据理解做最少 5 次可观察的真人走查；将 2 个经审核的已有机会样板补齐「谁付钱、模式、证据、未知、第一步」；研究页不得捏造事实。
- 企业：选一个垂直场景假设（默认电商商品内容生产，不是市场赢家结论）；访谈至少 5 家有明确业务问题的企业，完成 2 份匿名内部需求诊断练习；不接收未授权私人信息。
- 成果：第一版真实用户障碍列表、真实需求簇与竞品比较，不以页面数量替代验证。

**第 31–60 天：**
- 主线：总计接触约 15–25 个符合目标的真实创业研究用户，观察至少一周后的自愿再使用、第二次研究、信息可信性反馈；若没有留存理由，先改善内容深度与筛选决策，而不是强推登录。
- 企业：累计约 10–15 次企业问题访谈，人工核实至少 3 个愿意接受验收约束的候选提供方；制定一套可以无敏感数据演示的标准化 PoC 说明。
- 成果：客观记录愿意实际支付的咨询/研究/诊断意愿，区别免费反馈与真实成交。

**第 61–90 天：**
- 主线：目标累计约 30 名真实目标用户，观察真实 7 日复访、至少一种能被重复使用的机会研究路径；有需求再考虑保存/注册，而非反过来。
- 企业：有条件尝试 1 次真实付费诊断或小型 PoC（付款/合同与用户同意必须可核实）；复核交付效果、直接成本、返工和客户满意度。不得以意向/虚拟合同宣称成交。
- 成果：形成 KEEP / ADJUST / STOP 双线独立决策，付费及复购与网站流量不相互替代。

实验样本和百分比分配均为内部假设，**未经真实访问/访谈/收款前，结果栏一律 NOT_TESTED**。

## 5. 具体业务与技术交付 Gate

GATE-0 战略合同：本文件与 machine-readable config 一致，全量 CI 通过，未触及生产功能/数据库/Pages 路由。
GATE-1 核心用户价值：目标创业者能在 5 秒明白服务，并在既有研究页面完成找项目 → 判断证据 → 下一步流程（实际真人可用性单独记录，不能用单测顶替）。
GATE-2 企业需求质量：结构化访谈至少 5 个有真实问题的企业，客户同意、限制用途、明确无自动公示；不能建立未经授权的潜客名单。
GATE-3 试点：真实预算、需求负责人、可重复验收标准、合规数据处理，才允许参与人工 PoC；有真实付款证据才能标付费。
GATE-4 发布：任何账号、CMS、企业信息上传、云端 Worker 或匹配上线仍必须单独过原安全 Gate 与用户授权；GATE-0 的合并 **不能**开启任何云端功能。

**停止条件**：连续两批没有有效回访，则把资源转回机会内容与研究体验；企业访谈未出现重复痛点则暂停开发撮合市场；企业试点需高度定制无法复用，则缩窄一个场景而非开发更大交易系统。止损触发必须留样本和观察期，不得单凭主观喜好判断。

## 6. 已知的真实差距

- 没有经独立核实的真实产品市场匹配（PMF）或规模化留存证据；
- 尚无真实 CMS 用户账号正式上线、真实企业商机、服务商评价、付款/签约和可发布的交付结果；
- 现有合成/隔离技术 E2E 不等于真实用户安全、网站实际访问、真实企业采用或第三方安全审计；
- 如未拿到公开案例的权属和来源许可，站点只能使用已经审核的研究/案例摘要，禁止假造案例 KPI；
- 90 天阶段不是「网站一定上线交易」的承诺，而是以最低成本验证哪条路径有真实需求。
