# B1-QA｜390px / 1440px 真实浏览器验收方案

## 目标与边界

按 B0 冻结策略，以「创业者从首页 → 找项目 → 公司案例 → 研究来源和第一步」为主链路，企业方案和三个未开放入口只做可用性验收，不引入新业务功能。

**真实浏览器、但不是物理设备：** 使用 GitHub Actions 上真正的 Chromium 内核和 Playwright，通过本地 HTTP 打开由源码重新构建的公开 web/dist。模拟 390px 手机视口（含触控）和 1440px 桌面视口。它不是线上 Cloudflare CDN 的交互测试，不是肉眼设计师评审，也不是五位真实创业者用户测试。

## 检查内容

- 每种宽度下 10 个真实 HTML 路由，共 20 张完整网页截图；每页主标题存在、HTTP 200、DOM 单个 main、页面宽度没有超出窗口。
- 首页桌面导航/移动折叠菜单、首页进入找项目的链接。
- /projects/ → Carrd 详情 → 展开案例经营证据；没有新增虚构案例。
- /discover/：默认 9 个研究案例/模式，切换 3 家公司和 6 种模式，输入无结果词、空状态与重置、展开资料和相关内容。
- /solutions/：四方向、类别/关键词、无结果与重置。
- /marketplace/、/talent/：打开准备清单、勾选和清零，进入已存在的浏览器本地编辑器。
- /academy/：切换至自动化学习方向，验证原内容隐藏/新内容出现，实际勾选记录。
- 需求和作品草稿：写入虚构样例、生成内容、清除；不进行任何后台提交。
- JS 运行错误与非本站外部请求屏蔽：浏览器只允许 127.0.0.1 静态页面加载。

测试结果与 390/1440 PNG 图片通过单独 GitHub Artifact 保存七天，便于逐页视觉复核。此浏览器工作流独立于正式 P4.41 静态发布流程，不改 private claim、日采集预算或 Supabase 数据库。

## 验收判断

1. GitHub Action 必须明确 SUCCESS，且中文报告中失败数量 0；有自动浏览器失败时不能合并。
2. 执行成功只能表明自动交互/HTML 宽度/PDF 之外的真实截图已经生成；仍需人打开截图检查文字换行、间距、颜色层级。
3. **NOT_TESTED：** 生产 Cloudflare CDN 完整浏览器交互、真实设备触控、无障碍屏幕阅读器、五位真实创业者理解与任务完成率；这些项目未做不能宣称 PASS。
4. 若出现水平溢出、交互错误、404 或 JS 报错，以源文件修复，完成 CI 后再合并；不直接改 web/dist。

## 工作流入口

\`.github/workflows/browser-smoke.yml\`，在相关源码 PR、相关源码推送 main 或手动触发时执行。
