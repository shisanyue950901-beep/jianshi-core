# P4.16｜具名海外项目多维筛选与分类边界（2026-10-09）

## 用户价值
在“发现项目”现有“全部／具体项目／商业模式”和关键字搜索下方增加三组常见商业问题的下拉筛选：

1. **交付形式**：数字产品／软件、实体商品／图书、专业服务、内容媒体；
2. **收费方式**：持续订阅、商品／作品销售、交易手续费、广告／推荐佣金、项目／定制合同；
3. **客户对象**：企业／专业客户、个人消费者／创作者。

用户可以同时选择多个不同维度筛选；同一维度单选、维度之间取交集。选择多维条件后自动切换“具体项目”；清除后恢复原有类型搜索。六种商业模式指南保留原筛选逻辑，不会被误归类为具名经营项目。

## 资料和边界
来源于 P4.12C、P4.13、P4.15 已查证的公开经营信息，以 `config/p416_editorial_facets.json` 作为**内部编辑审核清单**。20 个具名项目都有三个维度标签；收入渠道可以有多个标签，客户对象也可以同时企业与个人。

### 不可把标签等同于事实认证
- “订阅”“交易手续费”“作品销售”仅代表官网公开销售机制或编辑归类，不代表已核实实际收入构成或交易额。
- “企业客户”与“个人用户”是潜在客群定位，不代表真实成交客户统计。
- 实体图书不等于由作者自行备货，因此本阶段**暂不添加“是否需要库存”筛选**。
- Designjoy、ManyPixels、Superside 属于不同规模/组织形式的服务案例，不把成熟企业当作已验证的单人创业样本。
- 不推断利润、员工人数、真实获客费用、品牌盈利或回报率。

## 开发与发布安全
- 仅改变发现区域 HTML/CSS 和已有单一脚本内的编辑标签逻辑；3D 动画仍为 8 个内嵌 WebP，滚动、灯箱、开屏、触屏和 reduced-motion 逻辑不改。
- 原始 8 条档案的重复 `search` 文本由运行时从既有字段生成，保留中英文搜索信息并降低 HTML 体积。
- 三组 `<select>` 使用真实 `<label>`、44px 触控高度、键盘原生操作；筛选动作不需要网络、账号或数据采集。
- 新标签内部 JSON 不能单独复制到 Cloudflare 公共构建目录；生产仍只发布 `web/dist`。
- 单文件 UTF-8 必须小于 250000 字节，沿用旧自动化发布、安全扫描、内容数量回归及 P4.16 新测试。
- 基于 PR #74 的开发分支；PR #74 又依赖 PR #73，**按 #73 → #74 → 本 PR 顺序审核**。不能为了加快发布绕过 Cloudflare 后台配置核对。

## 分阶段验收
- 源码自动化：20 个项目标签集合及结构一致、三维筛选契约、标签恢复、8 张主视觉、单文件上限、脚本语法、敏感目录扫描。
- 浏览器：26 条总结果、20 个具名项目、6 种商业模式；SaaS + 订阅、平台 + 手续费、专业服务 + 企业、无结果及清除、跨筛选器切换；桌面和 320/390px 手机。
- 真机 Safari、历史 Cloudflare 预览/缓存、产品财务事实仍保留 PENDING，不应填写 PASS。
