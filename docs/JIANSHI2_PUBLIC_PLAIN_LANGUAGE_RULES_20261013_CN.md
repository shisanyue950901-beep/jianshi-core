# 见势公开页面「一眼看懂」强制产品规则（2026-10-13）

**长期规则：用户一眼看不懂的术语、解释、技术分级、工程建设过程，不应该出现在面向用户的页面。** 本规则由产品负责人确认，覆盖首页、商业机会、研究详情、企业 AI 方案、商机、人才、学院、本地需求草稿以及未来新增业务页；不只是首页文案修订。

## 1. 页面统一要回答什么

- **找创业项目的用户**：是什么生意？谁使用？谁实际付钱？怎么赚钱？上手需要什么？有什么不能确定？我怎样开始验证？
- **想用 AI 的中小企业**：能帮我解决什么？适合什么企业？需要我提供什么？大概能交付什么？注意什么？
- **想学技能的人**：我能学什么？能做出什么作品？能不能现在上课？
- **想找合作的人**：这里能干什么？目前开放了吗？我现在可以准备什么？

每屏优先突出一个用户任务和一个主按钮。核心内容在手机端也能先看到。公开案例仅有 **3 个具名历史经营案例**，不可包装成三个可保证赚钱的项目。

## 2. 页面禁止直接出现的内部表达

- **不向用户展示**：L1/L2/L3/L4、OPP_V0.2、P4.4x、B1、G2、安全 Gate、CMS、Fail Closed、Workflow、Snapshot、Sandbox、审核引擎、数据表和部署状态。
- **不用作标题或模块导航**：CONTENT / EDITORIAL、SOLUTION CATALOG、PAIN POINT、GOOD FIT、DELIVERABLES、QUALITY GATE、CURRICULUM PLAN、FOUNDERS WORKBOOK 等英语阶段标签。
- **禁止无用长篇**：独立于实际问题的技术定义、建设流程宣言、重复免责声明和「我们如何审核」的冗长正文。
- **不应误导**：不能把用户当付费方，把公开定价当真实成交，把历史公司收入当新的个人创业利润，也不能虚构客户、企业需求、已交付案例、老师和课程。

## 3. 应该怎样写

| 旧说法 | 新说法 |
|---|---|
| 研究决策卡 / 证据层级 | 适不适合你做？／资料从哪里来？ |
| 经营证据 L3／L4 | 企业自己公开的历史说法／公开财报 |
| 下一步验证 / Gate | 第一步怎么做？／什么情况下别继续投入？ |
| 商业机会研究档案 | 创业项目介绍 |
| AI 企业自动化工作流 | AI 帮你处理重复工作 |
| 交付物与验收标准 | 最终应该拿到什么？ |
| 本地 Draft / Enterprise Request | 写下你的需求（不会上传） |
| CURRICULUM PLAN | 你能学哪些 AI 技能？ |

**关键原则：删除用户不需要的内部标签，不是删除事实。** 涉及真实收益、数据权属、版权和安全的必要说明仍需保留，但优先用一句话直说；有来源链接供用户自主查证，不把整套审计制度塞到页面首屏。

## 4. 工程和发布约束

- 本规则修改的是**公开展示文案、信息顺序和可读性**，不修改来源准入、历史财务原始数据、唯一官方发布器及静态生成位置。
- 只修改正式构建源模块。禁止手工改 `web/dist` 等生成文件后绕过 CI。
- CMS、登录、企业交易与支付仍关闭；生产数据库和 Cloudflare Worker 不写入。P4.41 每日私有采集计划、预算和验证链不变。
- 所有发布后必须再做 **用户可见文字审计**，检查中文是否通顺、没有英文字段、按钮可点击及风险提示真实。
- CI 能检查字符串、来源和内容顺序，但 **不能替代真实手机画面和真人看懂的事实**。B1 用户测试阶段继续记录真实理解误差。

## 5. 长期验收标准

每次页面发布审核必须先问五个问题：
1. 用户五秒内能说出这里能帮他做什么吗？
2. 不阅读背景说明，能否找到一个可执行的按钮？
3. 卡片是否直接回答用户实际关注的事？
4. 使用普通生活/商业中文，不需要懂技术/投资/合规才能看懂吗？
5. 即使文案精简了，来源限制、真实付款方、经营不确定性是否仍准确？

任意一项没有通过，**拒绝作为可用产品页面交付**。

B0 双线定位仍然有效：**个人创业机会发现为主，中小企业 AI 落地服务为第二业务**。
